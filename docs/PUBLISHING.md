# Публикация 2.3.34 на GitHub

Это инструкция для автора, не автоматический факт публикации. В данном пакете **нет готового Windows EXE**: его нужно собрать/проверить на Windows и прикрепить к Release отдельно.

## До публикации

1. Выберите владельца, имя и видимость репозитория. Возможное название — **PC-Monitor**; это предложение, не уже созданный репозиторий.
2. Выберите лицензию своего кода и добавьте LICENSE с корректным годом/правообладателем. Публичный репозиторий без лицензии не даёт автоматически открытые права на использование кода.
3. Проверьте права на сторонние PNG/GIF. ASSET-CREDITS — атрибуция, не лицензия. Если разрешения нет, не публикуйте эти файлы: замените разрешёнными материалами и обновите атрибуцию/тесты. Само удаление assets требует адаптации тестов наличия персонажей; не обещайте прежнее число пройденных тестов изменённому пакету.
4. Выполните Windows-чек-лист из AUDIT-2.3.34.md. Пройдите установку/обновление на другом ПК/пользователе. До проверки не называйте Windows-релиз гарантированно стабильным.

## Создание репозитория через сайт

1. GitHub → **New repository**.
2. Задайте имя, описание: «Локальный мониторинг ПК для Windows: CPU/GPU, датчики, FPS, темы и GIF».
3. Выберите Public/Private осознанно. Для публичного пакета сначала решите вопросы лицензии/материалов.
4. Загрузите **содержимое** подготовленной папки, чтобы README.md находился в корне, а не внутри ещё одного каталога.
5. При загрузке через сайт не забудьте скрытые `.github`, `.gitignore` и `.pc-monitor-source`. Для полного проекта с бинарными ресурсами удобнее Git/GitHub Desktop, чем drag-and-drop браузера.

## Загрузка через Git

Вместо заполнителей укажите собственные данные, не оставляйте их буквально:

```text
git init
git add .
git commit -m "Release PC Monitor 2.3.34"
git branch -M main
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Репозиторий на GitHub должен быть создан заранее; для этих команд удобнее пустой remote без первого README-коммита. Git может попросить настроить реальные user.name/user.email — используйте свои данные или GitHub noreply. Авторизацию выполняйте штатно; не публикуйте токены/пароли и не добавляйте их в URL/репозиторий.

EXE/ZIP/логи/временные файлы исключены .gitignore; бинарный EXE прикрепляется к Release, не коммитится в исходники. Проверяйте `git status` перед коммитом.

## Сборка для Release

В исходной папке на Windows:

```bat
build_windows.bat --keep-sources
```

**Для Git-клона обязательно используйте --keep-sources**, иначе успешная обычная сборка удалит весь исходный репозиторий, включая .git. Проект держите, например, в `D:\Projects\PC-Monitor`, а не прямо в `D:\PC-Monitor`.

Готовый файл: `X:\PC-Monitor\PC-Monitor.exe`. Проверьте его запуск без исходников/Python, источники датчиков, трей/F11/Topmost, положение, автозапуск и обновление.

Хэш PowerShell:

```powershell
Get-FileHash "D:\PC-Monitor\PC-Monitor.exe" -Algorithm SHA256
```

Запишите **реальный** хэш в Release; не используйте хэш ZIP вместо EXE и не заполняйте его выдуманным значением.

## Создание Release

1. GitHub → **Releases → Draft a new release**.
2. Tag: **v2.3.34**; target — проверенный commit main.
3. Title: **PC Monitor 2.3.34**.
4. Возьмите текст из [RELEASE-NOTES-2.3.34.md](../RELEASE-NOTES-2.3.34.md), добавьте фактические результаты Windows-проверки и SHA-256 EXE.
5. Прикрепите **PC-Monitor.exe** и, по желанию, свой ZIP исходников. GitHub Source code.zip добавляется автоматически и не является готовым EXE.
6. До завершения Windows-проверки используйте Draft/Pre-release. Не заявляйте тестирование, которого не было.
7. После проверки опубликуйте Release. Проверьте ссылки из README и скачивание с другого аккаунта/ПК.
