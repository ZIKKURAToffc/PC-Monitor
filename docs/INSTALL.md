# Установка

[Главная](../README.md) · [Настройки](PARAMETERS.md) · [Проблемы](TROUBLESHOOTING.md)

## 1. Требования

- Windows 10/11 x64; доступ к своей папке и системному TEMP.
- Для готового EXE Python не нужен. Для сборки — Python 3.10+ x64, интернет для pip; рекомендован Python 3.13.
- psutil читает основные данные ОС. Аппаратные температуры/мощность/вентиляторы требуют подходящего AIDA64/LHM/драйвера; FPS обычно требует RTSS и экспорта в AIDA64. Эти программы устанавливаются отдельно законным способом.

## 2. Готовый файл из Releases

В Releases ищите отдельный прикреплённый **PC-Monitor.exe**. Автоматические ссылки **Source code (zip/tar.gz)** — исходники, не готовая программа.

1. Создайте постоянную папку, например `D:\PC-Monitor`.
2. Поместите EXE туда и запустите. Не запускайте из самого ZIP или временной папки загрузчика.
3. При необходимости создайте ярлык Windows вручную. Скачанный отдельно EXE сам не создаёт ярлык: это делает сценарий сборки.
4. Подключите источник по инструкции ниже.

Темы/GIF и Python/Qt входят в onefile-EXE. При запуске PyInstaller временно распаковывает встроенные файлы в TEMP; доступ к этой папке нужен. Работа в трее не скрывает само окно: оно остаётся на рабочем столе.

## 3. Сборка из исходников

1. Сохраните исходный ZIP вне папки, которую будете распаковывать.
2. Распакуйте в отдельную папку, например `D:\Downloads\pc-monitor-desktop-v2.3.34`.
3. Установите x64 Python с PATH. Проверка в терминале: `py -3 --version` либо `python --version`.
4. Запустите `build_windows.bat`.
5. После успеха откройте `D:\PC-Monitor\PC-Monitor.exe` (или соответствующий диск проекта). Ярлык PC Monitor на рабочем столе указывает туда.

**Обычная сборка полностью удаляет исходную папку после успешной установки EXE, включая находящиеся внутри архивы, .git, старую .venv и личные файлы.** ZIP/личные файлы держите снаружи. Для проекта из Git или будущих правок:

```bat
build_windows.bat --keep-sources
```

Запускайте команду из терминала в исходной папке; двойной щелчок не передаёт параметр. Сама временная среда сборки удаляется и с `--keep-sources`.

Не распаковывайте исходники прямо в `X:\PC-Monitor`; это место назначения EXE. Используйте вложенную папку Downloads/Projects. Проект должен лежать на локальном диске с буквой; UNC-пути сборки не поддерживаются.

При ошибке компиляции/копирования старая установленная версия и исходники сохраняются. При блокировке удаления может остаться часть исходников: сценарий сообщает путь, остаток можно удалить вручную после закрытия использующих его программ. Глобальный Python не удаляется.

Для записи в корень диска может понадобиться право администратора. Автоматического повышения прав нет; используйте запуск BAT от администратора только если обычному пользователю отказано и вы доверяете проекту. Не отключайте антивирус/защиту ОС. Если ярлык не создался, создайте его вручную либо, при сохранённых исходниках, запустите `create_shortcut.bat`.

## 4. Запуск исходников без компиляции

`start_windows.bat` создаёт `.venv`, устанавливает зависимости и запускает LIVE-режим. Этот запуск исходники не удаляет. Для сообщений консоли используйте `debug_windows.bat`.

Пример после установки зависимостей:

```bat
.venv\Scripts\python.exe desktop.py --demo
```

DEMO — синтетические данные, не реальные показания. Автозапуск включается только в готовом Windows EXE; Linux/macOS не являются целевой платформой этого релиза.

## 5. AIDA64

Ориентир интеграции — **AIDA64 Extreme 8.00.8000**; версия не определяется по XML, другие выпуски требуют проверки совместимости экспорта.

1. В AIDA64 откройте **Preferences → Hardware Monitoring → External Applications**.
2. Включите **Enable shared memory**.
3. Отметьте необходимые датчики: температуры, CPU Clock, загрузку, мощность, RPM и RTSS FPS при наличии.
4. Оставьте AIDA64 открытой.
5. В PC Monitor: **⚙ → Подключить датчики → Подключение → AIDA64 → Применить**.
6. На вкладке **Датчики панели** выберите источники и снова нажмите **Применить**.

Чтение локальное через Shared Memory. Порт и пароль не нужны. При отказе доступа проверьте пользователя и уровни прав AIDA64/монитора, не изменяя защиту ОС.

## 6. LibreHardwareMonitor (LHM)

1. Установите/запустите LHM из официального проекта и убедитесь, что нужные показания есть в его окне.
2. Включите **Remote Web Server → Run**; используйте локальный порт, стандартно **8085**.
3. В PC Monitor выберите **LHM: только HTTP** для новых версий или **HTTP → WMI** для совместимого старого выпуска.
4. Укажите порт, при включённой Authentication — имя пользователя и пароль. Пароль используется только в текущем сеансе и не сохраняется.
5. Нажмите **Применить** и дождитесь обновления списка датчиков.

Клиент обращается только к `http://127.0.0.1:<порт>/data.json`, не использует proxy и не следует перенаправлениям. Не открывайте сервер в интернет; при необходимости настройте ограничения доступа сервера/ОС. **WMI — для старых версий LHM**; в новых используйте HTTP.

## 7. FPS: RTSS + AIDA64

1. Запустите RTSS и игру. Профиль RTSS должен относиться к EXE самой игры, не только лаунчеру; Application detection level не должен быть None.
2. Убедитесь, что RTSS сам показывает ненулевой FPS.
3. В AIDA64 включите Shared Memory и экспорт **RTSS FPS / SRTSSFPS**.
4. В PC Monitor назначьте FPS: **Авто** либо соответствующий датчик **RTSS FPS** с единицей FPS.
5. Проверьте вкладку **FPS** в окне подключения.

Если RTSS показывает 0, переустановка PC Monitor не исправит отсутствие кадров у источника. Некоторые игры/античит ограничивают мониторинг: не обходите защиту. Имя процесса читается отдельно из RTSS; AIDA64 не подтверждает привязку общего FPS к этому PID.

## 8. Обновление и удаление

Перед заменой EXE полностью выйдите через трей/закройте программу. Установите новый EXE в ту же постоянную папку. Положение и пользовательские настройки сохраняются отдельно от исходников.

Если EXE перемещён и включён автозапуск, откройте его из новой папки и сохраните настройки с включённым автозапуском, чтобы обновить путь. До удаления приложения отключите автозапуск. Затем удалите EXE/ярлык; внешние AIDA64/LHM/RTSS удаляются отдельно по желанию пользователя.
