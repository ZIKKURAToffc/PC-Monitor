# PC Monitor Desktop 2.3.34

Нативное приложение PySide6 для мониторинга ПК: CPU/GPU, температуры, мощность, вентиляторы, память, сеть, диски и FPS. Чтение датчиков локальное. Интерфейс русский, украинский и английский.

## Изменения 2.3.34 — аудит устойчивости

Подробный отчёт — **AUDIT-2.3.34.md**. Основные исправления:

- Повреждённые числовые настройки и вложенные структуры карточек больше не мешают запуску; корректные назначения и прочие настройки сохраняются.
- Временная ошибка первого запроса ОС не завершает системный поток. Отсутствие сетевых интерфейсов не мешает CPU/RAM; повторный start не дублирует потоки.
- Поколения конфигурации не дают запоздавшему ответу прежнего источника вернуть старые показания или диагностику.
- Защищены числовые преобразования, malformed LHM/FPS metadata, строковые VRAM и форматы разделителей. Некорректный датчик остаётся недоступным, а не заменяется выдуманным значением.
- Закрытые диалоги настроек/стилей/панели/подключения/разработчика освобождаются; таймеры и GIF-предпросмотр останавливаются.
- Перед заменой установленного EXE проверяется SHA-256 копии. Усилена защита source-root junction при автоматическом удалении.
- Добавлен локальный ограниченный журнал неожиданных Python-ошибок: **%LOCALAPPDATA%\PC-Monitor\logs\errors.log** (резервный путь в TEMP). Никакой автоматической отправки нет. Перед передачей лога другому человеку просмотрите его.
- Версия GUI/CLI-диагностики теперь общая. Все пользовательские текстовые подписи отображаются без HTML-интерпретации.
- Исправлен случай пустого ID часового пояса Qt, когда тестовое окружение показывало ошибочное UTC+00:00:01: используется реальный локальный offset ОС.
- Максимум своих карточек — 128; добавление снова доступно после удаления карточки.

**372 теста проходят**, production-модули проходят Pyflakes без замечаний. Сохранены положение окна, автозапуск по выбору пользователя, установка в X:\PC-Monitor и удаление распакованных исходников после успешной сборки. ZIP храните вне этой папки.

Это не гарантия отсутствия ошибок на всех ПК: реальную Windows-компиляцию, драйверы и живые Windows-источники здесь не запускали. Чек-лист проверки Windows включён в отчёт.

## Изменения 2.3.33 — положение окна между запусками

Окно восстанавливает последнее **расположение и размер**, а не перемещается в центр при каждом запуске. Исправлена причина: раньше после restoreGeometry безусловно выполнялся move в центр экрана.

- Перемещение и изменение размера сохраняются автоматически через 400 мс после последнего события и дополнительно при закрытии/выходе через трей. Нажимать «Сохранить» в настройках не требуется.
- Сохраняется нормальная геометрия окна и развёрнутое состояние. Запуск не остаётся свёрнутым. Если закрыть в полноэкранном режиме, следующий запуск использует прежнее обычное положение (или прежнее развёрнутое состояние), а не включает полный экран.
- «Поверх других окон», трей, перетаскивание и безрамочный полный экран не сбрасываются. Назначения датчиков и данные не меняются.
- Второй монитор и экраны с отрицательными координатами поддерживаются. Если монитор отключён, разрешение уменьшилось или окно оказалось вне рабочего пространства, оно возвращается в видимую область доступного экрана, с учётом рамки окна.
- Старые сохранённые geometry используются при отсутствии нового формата. Если настроек нет или они повреждены, первое окно размещается по центру видимой области.
- Настройки остаются в прежнем QSettings пользователя, вне папки исходников: её автоматическое удаление и пересборка не стирают положение окна. Функция работает и при добровольно включённом автозапуске Windows.

**320 тестов проходят**, включая повторный запуск, живое сохранение, полный экран, Topmost, развёрнутое окно и отключение монитора. Реальная Windows-компиляция и физическая смена нескольких мониторов здесь не выполнялись.

## Изменения 2.3.32 — удаление распакованных исходников

**Внимание: build_windows.bat теперь удаляет всю распакованную папку проекта после успешной компиляции и установки EXE.** Например: `D:\Downloads\pc-monitor-desktop-v2.3.32` удаляется; **D:\PC-Monitor\PC-Monitor.exe** остаётся. Ярлык создаётся до удаления исходников.

- Сохраняйте ZIP-архивы и личные файлы **вне папки исходников**. Всё внутри неё, включая assets, тесты, документацию, старые build/dist/.venv и помещённые туда архивы, будет удалено. Родительские папки и архивы рядом с проектом не затрагиваются.
- Удаление запускается только после успешной сборки и установки проверенного EXE вне исходной папки. Ошибка компиляции или переноса EXE сохраняет исходники. Собственная временная сборочная папка очищается отдельно.
- Удаляется только отмеченная файлом **.pc-monitor-source** папка этого проекта. Корень диска, домашняя папка, папка с установленным EXE, а также исходники с символическими ссылками/junction не удаляются автоматически.
- BAT переходит в системную папку перед вызовом Python, чтобы не удерживать исходную папку открытой. Финальный блок BAT заранее считывается командным интерпретатором и может закончить работу после удаления самого BAT.
- При блокировке файлов удаление повторяется. Если всё ещё не получается, выводится предупреждение: EXE остаётся на месте, часть исходников может остаться. Закройте программы, использующие исходную папку, и удалите остаток вручную. Права доступа и защита Windows автоматически не меняются.
- Необязательное исключение для разработки: **build_windows.bat --keep-sources** или **python -B build_windows.py --keep-sources** оставляет исходники. Обычный запуск BAT удаляет их без дополнительного подтверждения.
- Для будущего обновления распакуйте сохранённый ZIP заново. Исходники не нужны для работы EXE; AIDA64/LHM/RTSS остаются внешними источниками датчиков.
- Если ярлык не удалось создать, сборка EXE всё равно сохраняется: создайте ярлык вручную на установленный EXE. Автозапуск по-прежнему включается только в настройках программы.

Проверены **303 теста**, включая защиту путей и удаление тестовой папки с сохранением EXE и соседнего архива. Реальная сборка и самоудаление BAT в Windows здесь не выполнялись.

## Архивные изменения 2.3.31 — установка в корень диска

Запустите **build_windows.bat**. Готовый EXE теперь сохраняется в папку **PC-Monitor** в корне диска исходного проекта. Например: проект `D:\Projects\PC-Monitor` → **D:\PC-Monitor\PC-Monitor.exe**. Диск системного TEMP не влияет на выбор места установки.

- После успешной сборки обновляется ярлык **PC Monitor** на рабочем столе: он указывает на установленный EXE. Открывается его папка.
- Временная папка компиляции с зависимостями, кэшами и промежуточными файлами удаляется после успеха и ошибки. Если Windows блокирует очистку, сценарий сообщает оставшийся путь.
- Исходный проект не удаляется. В новой папке назначения остаётся только EXE; существующие посторонние файлы не затрагиваются. Все GIF и темы встроены в EXE, исходники для запуска не нужны.
- Прежний установленный EXE заменяется атомарно только после успешной компиляции. При ошибке сохраняется старая версия. Перед обновлением закройте запущенный монитор.
- Требуется право создания папки в корне выбранного диска. При отказе доступа сборка сообщает ошибку; автоматического повышения прав или изменения защиты нет. Если необходимо, запустите BAT от администратора самостоятельно.
- Проект должен находиться по абсолютному пути на локальном диске с буквой. UNC/сетевые пути не поддерживаются: перенесите исходники на локальный диск.
- **create_shortcut.bat** без аргументов использует тот же установленный EXE. Явный путь к перенесённому EXE можно передать аргументом.
- Автозапуск остаётся добровольным. Если он уже ссылался на старую папку, откройте новый EXE и сохраните настройки с включённым «Запускать вместе с Windows», чтобы обновить путь. Сборка сама не включает автозапуск.

Реальная Windows-компиляция здесь не выполнялась; пути, публикация, ярлык и очистка проверены автоматическими тестами с имитацией сборки.

## Архивные изменения 2.3.30 — чистая сборка

Запуск прежний: **build_windows.bat**. Сценарий вызывает **build_windows.py** и собирает один **dist\PC-Monitor.exe**, создаёт/обновляет ярлык на рабочем столе, затем удаляет свою временную сборочную папку.

- Python-среда сборки, установленные PyInstaller/PySide6/зависимости, work/build, `.spec`, кэши и промежуточные результаты находятся в уникальной папке **pc-monitor-build-…** внутри системного TEMP.
- Для pip отключён новый дисковый кэш; кэш PyInstaller и временные файлы дочерних процессов перенаправлены в эту же папку. Сборка через BAT использует `-B`, чтобы не создавать кэш Python в исходниках.
- Временная папка удаляется после успеха **и после ошибки**. Если Windows блокирует удаление, выводится предупреждение и точный путь оставшейся папки — приложение не скрывает неполную очистку.
- Только успешно собранный Windows EXE копируется в уникальный staging-файл внутри dist и атомарно заменяет **PC-Monitor.exe**. Ошибка компиляции/копирования/замены не удаляет прежний EXE. Если работающий EXE мешает замене, закройте его и повторите сборку.
- На чистой сборке в dist остаётся только EXE. Никакие другие пользовательские файлы в существующей dist не удаляются. Промежуточный staging-файл удаляется.
- **Исходники, assets/GIF, настройки приложения, существующая .venv, чужие/старые build-папки и пользовательские файлы сохраняются.** Автоматически удаляется только созданная текущим запуском временная папка. Исходники нужны для будущих исправлений; для запуска готового EXE папка исходников не требуется.
- Поскольку среда сборки удаляется, следующая сборка заново установит зависимости и потребует интернет. Глобальный Python и общий кэш pip пользователя не удаляются.
- Ошибка создания ярлыка не отменяет успешный EXE: используйте **create_shortcut.bat** для повторной попытки.

Все 16 GIF и темы по-прежнему встроены в EXE. Автозапуск, перетаскивание и безрамочный полный экран не изменены. **271 тест проходит**; реальная Windows-компиляция здесь не выполнялась.

## Изменения 2.3.29

- В настройках остался только ник разработчика **ZIKKURAT**. Кнопка открывает окно с ником и «Закрыть», без контактов, копирования контакта или переходов на внешние ресурсы.
- Добавлена опция **⚙ → Настройки → Запускать вместе с Windows → Сохранить**. Автозапуск выключен по умолчанию, сборка/первый запуск не включает его автоматически.
- Запуск происходит **после входа текущего пользователя в Windows**, не до экрана входа. Открывается обычное видимое окно с треем, без скрытого запуска или сворачивания. Полный экран автоматически не включается.
- Регистрация только для текущего пользователя: **HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run**, значение **PC Monitor**. Права администратора не нужны. Записывается абсолютный путь текущего EXE в кавычках; регистрация не запускает промежуточный командный интерпретатор.
- Для отключения снимите опцию и сохраните. Удаляется только значение PC Monitor; другие программы и записи Windows не меняются. Отмена настроек ничего не регистрирует.
- Если EXE перенесён, откройте его в новой папке и снова сохраните настройки с включённым автозапуском: ссылка на прежний EXE обновится. Перед удалением приложения отключите автозапуск.
- Настройка включения доступна только в собранном **Windows EXE**; при запуске исходников/на другой ОС она недоступна. Windows-источники позволяют удалить прежнюю запись, если она существовала.
- Состояние читается из реестра, а не из флажка QSettings. При отказе доступа сохранение останавливается с сообщением; окно настроек и введённые значения остаются открытыми. Ограничения безопасности Windows не изменяются и не обходятся. Windows может дополнительно блокировать запуск политикой или через «Автозагрузка» в диспетчере задач.

Автозапуск монитора не запускает AIDA64/LHM/RTSS: при необходимости настройте их запуск отдельно.

GIF, перетаскивание, безрамочный полный экран, ярлык и работа трея сохранены. **259 тестов проходят**; доступ к реестру проверен с имитацией, реальная регистрация/запуск при входе в Windows здесь не выполнялись.

При наведении на подписи появляется курсор открытой руки. Обычный системный заголовок также остаётся доступен.

## FPS

Штатный источник — **AIDA64 SRTSSFPS**, полученный AIDA64 от RTSS. Программа не захватывает кадры игры напрямую, не вычисляет FPS по загрузке GPU и не заменяет ноль выдуманным показанием.

В **⚙ → Подключить датчики → FPS** показаны источник, значение и исходная строка SRTSSFPS; там же есть инструкция проверки цепочки RTSS → AIDA64. Если сам RTSS не показывает FPS, нужно проверять установку, профиль и обнаружение игры. При положительном FPS в RTSS и нуле в AIDA64 проверяйте передачу и публикацию RTSS FPS в Shared Memory. Не отключайте защиту игр и не обходите ограничения ради мониторинга.

Приложение опрашивает AIDA64/HTTP с выбранным интервалом (стандарт 500 мс); частота публикации новых значений зависит от источника. Резервный NVIDIA CLI опрашивается не чаще раза в секунду, WMI — раза в 2 секунды. Ноль сохраняется как переданное значение; недоступные/некорректные/устаревшие данные объясняются отдельно.

## LHM

Для актуальных Libre Hardware Monitor используйте **Remote Web Server → Run**, локальный порт **8085**. Адрес чтения — `http://127.0.0.1:8085/data.json`. WMI поддерживается только как вариант для старых выпусков LHM; в 0.9.5 WMI отсутствует.

Не открывайте порт в интернет. При необходимости включите Authentication и ограничения доступа ОС. Имя пользователя можно сохранить, пароль не сохраняется. Во вкладке «Подключение» есть выбор HTTP/WMI, порт и поля авторизации.

## Диагностика и конфиденциальность

Во вкладке **Диагностика** и через «Копировать диагностику» доступны сведения о подключении, опубликованные значения и блок FPS. Названия оборудования, идентификаторы и диагностический JSON не переводятся. Сырые данные и экспорт могут содержать имена ПК, адреса, даты, названия устройств и имена/PID отслеживаемых RTSS-приложений — просматривайте файлы перед отправкой. Удаление личного имени из видимых подписей не изменяет исходные сведения ОС в экспорте.

Демо: `python desktop.py --demo`. Все значения такого режима синтетические; для реального мониторинга запускайте без `--demo`.


## Windows: ярлык и значок в трее — 2.3.26

После успешного завершения **build_windows.bat** автоматически создаётся или обновляется ярлык **PC Monitor** на рабочем столе текущего пользователя. Учитывается перенаправленный рабочий стол, в том числе OneDrive. Ярлык запускает **X:\PC-Monitor\PC-Monitor.exe** (X — диск исходного проекта) в обычном, не свёрнутом состоянии. Права администратора не нужны. Если создание ярлыка не удалось, сборка EXE сохраняется, а сценарий выводит предупреждение.

Если исходники сохранены или снова распакованы, для повторного создания ярлыка запустите **create_shortcut.bat**. Иначе создайте ярлык вручную на установленный EXE. Если перенесли EXE, передайте новый путь: `create_shortcut.bat "D:\Apps\PC-Monitor.exe"`. Старый ярлык сам путь не обновляет. Сборка сама по себе не включает автозапуск; он включается отдельно в настройках.

При обычном запуске в Windows окно **видно на рабочем столе**, без отдельной кнопки на панели задач; значок приложения остаётся в системном трее. Нажатие значка возвращает окно на передний план. Его меню: **Показать окно**, **Пауза / Продолжить**, **Настройки**, **Выход**. Переключение на другое приложение не скрывает и не сворачивает окно. Кнопка сворачивания в заголовке убрана; приложение не блокирует системные команды вроде «Показать рабочий стол» — после них окно можно восстановить из трея. **Крестик закрывает приложение**, а не прячет его.

Если системный трей недоступен, остаётся обычное окно с кнопкой на панели задач. При ошибке настройки Windows-стиля выполняется попытка отката; результат доступен в диагностике `windows_shell`. Скрытие из панели задач также исключает окно из стандартного переключателя Alt+Tab; возвращайте его через трей. На других ОС режим окна не меняется; для снимков экрана интеграция трея отключена.

В архиве исходники и сценарий сборки, **не готовый EXE**. Реальная компиляция EXE, Explorer, PowerShell COM и системный трей Windows здесь не запускались: проверены Qt offscreen и тесты с имитацией Win32/PowerShell.
