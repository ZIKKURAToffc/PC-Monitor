# Решение проблем

[Главная](../README.md) · [Установка](INSTALL.md) · [Параметры](PARAMETERS.md)

## Не запускается программа

- Убедитесь, что это Windows 10/11 x64 и настоящий `PC-Monitor.exe`, а не ZIP/папка исходников.
- Для исходников выполните `start_windows.bat`; сообщения консоли — в `debug_windows.bat`.
- Для готового onefile-EXE нужны права на TEMP. Не запускайте из ZIP.
- Проверьте `%LOCALAPPDATA%\PC-Monitor\logs\errors.log`; резервный путь — `PC-Monitor-logs` в TEMP. Журнал фиксирует Python-исключения, не все нативные аварии Qt/драйверов.
- SmartScreen/антивирус может блокировать неподписанный EXE. Проверьте происхождение/хэш файла и правила своей системы; не отключайте защиту ради запуска неизвестного файла.

## «—» вместо температуры/мощности/вентилятора

Это недоступное значение, не ошибка форматирования и не ноль. Проверьте наличие датчика во внешнем источнике и его экспорт. Откройте **Датчики панели**, выберите совместимый источник и нажмите **Применить**.

При исчезнувшем/неподходящем явном ID программа не подставляет другой датчик. Для автоматического выбора явно переключите на **Авто**. GPU Memory не заменяется Hotspot; PWM (%) не является RPM. Не все видеокарты публикуют температуру памяти, мощность или обороты.

## Нет связи с AIDA64

Проверьте, что AIDA64 открыта, включён **Enable shared memory**, отмечены нужные датчики. Порт/пароль LHM не влияют на Shared Memory. При Access denied проверьте пользователя и уровни прав обеих программ; не отключайте защиту.

## Нет связи с LHM

Проверьте **Remote Web Server → Run** и порт. Должен отвечать локальный `127.0.0.1:<порт>/data.json`.

- HTTP 401: нужны пользователь/пароль Authentication.
- HTTP 403: сервер отказал в доступе.
- HTTP 404: неверный порт/сервер без data.json.
- WMI вернул 0 датчиков: для нового LHM используйте HTTP.

Не открывайте порт в интернет. Не публикуйте пароль в Issue/скриншоте.

## FPS = 0

1. Проверьте ненулевой FPS в самом RTSS во время игры. Если RTSS показывает 0, PC Monitor также не получает реальные кадры.
2. Профиль RTSS должен относиться к EXE игры, не только лаунчеру; detection level не None.
3. Проверьте экспорт SRTSSFPS в AIDA64 Shared Memory.
4. В **Датчики панели** назначьте **RTSS FPS** с единицей FPS.
5. Откройте вкладку **FPS**: если RTSS показывает кадры, а AIDA64 экспортирует 0, проблема в передаче RTSS → AIDA64.

Переустановка RTSS иногда помогает повреждённой установке, но не гарантирует совместимость с любой игрой. Не обходите античит и не отключайте защиту. Разрешённый встроенный счётчик игры может быть единственным доступным вариантом.

## FPS есть, но имя приложения неизвестно

Число FPS и имя читаются отдельно. Имя зависит от свежих метаданных RTSS, числа активных приложений и выбранного FPS-источника. При временной ошибке подтверждённое имя может сохраняться до 3 секунд; при пустой таблице оно очищается. Несколько приложений не приводят к произвольному выбору одного имени. AIDA64 не подтверждает привязку общего FPS к конкретному PID.

## Данные обновляются медленно

Установите интервалы интерфейса/опроса 500–1000 мс. Затем проверьте темп публикации AIDA64/LHM. Опция 250 мс не заставляет источник публиковать новые значения. WMI/NVIDIA имеют дополнительные ограничения. Длительные аппаратные запросы также увеличивают задержку.

## Нет портрета/анимации

Портрет скрывается при нехватке свободного места, в том числе на узком окне. Выберите аниме-тему, включите персонажей и анимацию; увеличьте окно. Если GIF недоступен/неподдерживаем, используется резервный PNG. Выключенные визуальные эффекты не обязательно отключают GIF: проверяйте отдельный флажок анимации.

## Окно не там / нет кнопки на панели задач

В Windows с доступным треем отсутствие отдельной кнопки панели задач — ожидаемое поведение. Нажмите значок трея → **Показать окно**. Крестик закрывает программу полностью.

Положение сохраняется после изменения и закрытия. Отключённый монитор/смена разрешения могут вызвать корректировку положения в видимую область. В полном экране перетаскивание отключено; нажмите Escape. Если настройки не сохраняются, проверьте права пользователя на QSettings/реестр; не удаляйте вручную чужие записи реестра.

## Автозапуск не работает

Опция включается только в собранном Windows EXE через **Сохранить**. Запуск происходит после входа текущего пользователя, не до экрана входа. После переноса EXE снова сохраните включённую опцию из нового места. Windows/корпоративная политика может блокировать автозапуск независимо от записи; проверьте «Автозагрузка» и правила системы. Внешние AIDA64/LHM/RTSS монитор сам не запускает.

## Сборка / удаление исходников

- Ошибка создания папки `X:\PC-Monitor`: проверьте доступ к корню диска; при необходимости доверенный BAT можно запустить от администратора.
- Старый EXE не заменяется: полностью выйдите из монитора; проверьте блокировку антивирусом/другим процессом.
- Осталась временная/source-папка: сценарий сообщает блокировку; закройте использующие её программы и удалите остаток вручную. Не удаляйте папку с установленным EXE.
- Исходники удалены после успешной сборки: это стандартное поведение. ZIP сохраняйте снаружи; для разработки `--keep-sources`.
- Исходники находятся в UNC/сетевом пути: перенесите на локальный диск с буквой.

## Как сообщить об ошибке

Создайте Issue по шаблону: версия, Windows/x64, оборудование, источник и его версия, шаги, ожидаемое/фактическое поведение. Приложите только проверенные и очищенные фрагменты логов/диагностики. Не отправляйте пароли, токены, пользовательские пути или hostname, если не хотите раскрывать их.
