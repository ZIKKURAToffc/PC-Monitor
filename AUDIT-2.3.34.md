# Аудит PC Monitor 2.3.34

## Область проверки и ограничения

Просмотрены запуск и persistent settings, GUI/диалоги/таймеры/геометрия, источники AIDA64/LHM/NVIDIA/psutil, ручные назначения, FPS и RTSS, темы/GIF, трей/Win32-флаги, автозапуск, сборка/копирование EXE/ярлык/удаление исходников и CLI-диагностика.

Это проверка исходников и автоматические тесты, **не гарантия отсутствия всех ошибок на любом ПК**. Среда: Linux, Python 3.13.14, PySide6 6.12.0, psutil 7.2.2; Qt UI проверяется в offscreen-режиме. Реальные Windows API, компиляция Windows EXE, драйверы GPU, физические мульти-мониторные конфигурации и живые AIDA64/LHM/RTSS здесь не запускались. Эти пути проверены имитациями и тестовыми данными, где доступны.

## Найденные и исправленные проблемы

### 1. Повреждённые числовые настройки мешали запуску

Прямой int() над сохранённым значением мог вызвать ValueError/TypeError. Нулевые/отрицательные интервалы и бесконечные значения не проверялись. Добавлена проверка порта, режима источника, интервала интерфейса, истории, порога и опроса. Некорректные значения получают безопасное стандартное значение, остальные настройки не сбрасываются. Восстановление позиции осталось совместимым с предыдущей версией.

### 2. Некорректная вложенная конфигурация карточек

Одной проверки внешнего dict недостаточно: slots мог быть списком, отдельная карточка — null, custom — строкой/неверным списком, label — числом. Добавлена нормализация структуры, типов и длины подписей/идентификаторов. Пользовательские карточки ограничены 128; интерфейс не позволяет превысить лимит и снова разрешает добавление после удаления. Корректные ручные ID сохраняются; исчезнувший/несовместимый выбранный датчик по-прежнему отображается как «—», без подмены.

### 3. Поток системных данных мог завершиться до обработки ошибок

Начальные запросы psutil находились вне try. Временная ошибка первого запроса сети/времени загрузки могла остановить поток. Инициализация перенесена в защищённый цикл с повторной попыткой. Отсутствие сетевых интерфейсов больше не мешает CPU/RAM: сетевые значения недоступны, а не выдумываются. Повторный start() не запускает дублирующие живые потоки.

### 4. Запоздавший ответ прежнего источника

При переключении источника старый запрос мог закончиться позже и снова опубликовать старые данные/диагностику. Конфигурация имеет поколение; состояние очищается при реальном изменении. Результат фонового опроса/диагностики публикуется только если поколение совпадает. Защищены аппаратный и системный потоки.

### 5. Числовые крайние случаи

Исключено принятие True/False за числовой датчик. Очень большие int, NaN/Infinity обрабатываются без OverflowError. Сохраняется корректный ноль. Исправлена обработка VRAM, если числовые значения представлены строками. Graph.push нормализует входные значения. LHM принимает оба вида смешанных разделителей: 1,234.5 и 1.234,5; повреждённый SensorId/Children не ломает соседние корректные датчики. Некорректная структура sensor_rows/RTSS metadata безопасно игнорируется.

### 6. Накопление закрытых окон настроек

Родительский QMainWindow удерживал закрытые QDialog. После чтения выбранных значений теперь вызывается deleteLater для настроек, стилей, разработчика, панели и подключения. Таймеры закрытых диалогов останавливаются, проигрыватели предпросмотра также останавливаются. Тесты повторных открытий проверяют отсутствие оставшихся QDialog.

### 7. Целостность установки и границы удаления

До атомарной замены EXE проверяются размер и SHA-256 исходного/скопированного файла. Даже повреждение копии с неизменным размером не заменяет предыдущий EXE. Сохранён временный staging и его очистка. Корневая source-папка дополнительно проверяется на Windows reparse/junction до разрешения пути. Сохранены защита маркера/drive root/home/EXE внутри исходников, предупреждения о блокировках и --keep-sources. ZIP вне распакованной папки не удаляется.

### 8. Ошибочная версия CLI-диагностики

В diagnose.py оставалась 2.1.3. Версия теперь общая с GUI через app_metadata.py. CLI не выполняет запросы при импорте и сообщает отказ записи без неперехваченного исключения; Collector закрывается в finally.

### 9. Неожиданные ошибки EXE без консоли

Добавлены обработчики неожиданных Python-исключений и локальный журнал:

`%LOCALAPPDATA%\PC-Monitor\logs\errors.log`

Если запись туда невозможна, используется PC-Monitor-logs в TEMP. До двух архивных логов, максимум около 256 KiB на файл при обычных записях. Большая единичная запись может превысить лимит файла; ротация ограничивает число файлов. Данные никуда не отправляются. Лог не снимает значения локальных переменных/сохранённых паролей: только обычный traceback и сообщение исключения. Путь/текст исключения может содержать имя пользователя или другую диагностику — просмотрите перед передачей другим людям. GUI-предупреждение ограничено по частоте; фоновый Python-поток не открывает GUI-диалог. Нативные аварии Qt/драйвера этим обработчиком не перехватываются.

### 10. Пользовательские подписи могли интерпретироваться как HTML

Общие QLabel и ElideLabel теперь используют PlainText. Текст вроде `<b>Sensor</b>` выводится буквально, а не меняет разметку и не загружает изображение из подписи. Функциональные кнопки и официальные ссылки не изменены.

### 11. Ложное смещение UTC на секунду

На проверочном запуске Qt сообщил пустой systemTimeZoneId, а systemTimeZone() вернул UTC+00:00:01, хотя ОС была UTC. Теперь при доступном ID зона создаётся явно из него; иначе используется native local time/offset. Это не угадывание зоны по языку и не принудительное округление: явно заданная зона со смещением в секунду и DST продолжают поддерживаться.

## Результаты проверок

- **372 автоматических теста**, включая 52 новых проверки аудита.
- AST/синтаксис: 57 Python-файлов, без синтаксических ошибок.
- Pyflakes для production-модулей: **0 замечаний**. Для тестовых файлов ранее найдены только неиспользуемые импорты/локальные переменные; это не ошибки исполнения.
- Реальный локальный smoke-test Collector на Linux: CPU/RAM собираются, повторный start не дублирует два потока, переключение режимов и close проходят без неперехваченных исключений, потоки завершаются.
- Отдельный старт GUI с изолированными настройками и screenshot: интерфейс отображается, журнал ошибок пуст. Дополнительно проверены старые FPS/семантические фильтры, темы/GIF, окно/позиция/F11, автозапуск, ярлык и очистка.
- Для итогового Windows EXE все 16 GIF и резервные PNG остаются локальными ресурсами; зависимости не должны находиться рядом с EXE. AIDA64/LHM/RTSS по-прежнему отдельные программы.

## Чек-лист проверки Windows перед распространением

1. Windows 10/11 x64, обычный и ограниченный пользователь; пути с пробелами/кириллицей, диски C/D, запрет создания папки в корне диска.
2. Собрать через build_windows.bat, проверить установленный EXE, ярлык, удаление TEMP/source, сохранность соседнего ZIP и старого EXE при ошибке. Проверить запуск EXE без исходников и Python.
3. Повторить настройку автозапуска, проверить после выхода/входа пользователя. Сборка не должна сама включать автозапуск. Проверить путь после переноса EXE.
4. Проверить настоящее окно/трей, F11/Topmost/перетаскивание/восстановление положения и второй монитор; отключить второй экран и изменить DPI.
5. Проверить AIDA64 shared memory, LHM HTTP (включая Authentication), старый WMI при наличии; отсутствие источника, отключение/возврат, переключение во время опроса. Не отключать защиту Windows ради мониторинга.
6. Проверить реальный NVIDIA driver, AMD/Intel без NVIDIA, несколько GPU; выбранные источники карт не должны автоматически подменяться.
7. Проверить RTSS/AIDA64 FPS в поддерживаемой игре, несколько приложений, завершение игры, отсутствие RTSS. Античит-совместимость зависит от игры/RTSS; программа сама не внедряется в игру.
8. Проверить часовой пояс/DST и RU/UK/EN, обычные/аниме-темы, несколько повторных открытий диалогов и длительный запуск. Проверить ошибки записи настроек/логов и доступность TEMP для распаковки PyInstaller onefile.
9. Windows SmartScreen/антивирус/корпоративные политики могут ограничивать неподписанный EXE. Проверять и подписывать релиз штатными средствами; не рекомендовать отключать защиту. Перед публичным распространением также проверьте права на внешние изображения/GIF из ASSET-CREDITS.md.
